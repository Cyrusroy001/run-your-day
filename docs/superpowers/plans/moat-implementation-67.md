The Drift Engine: Operational MechanicsThe core engine pipeline uses a deterministic loop to process incoming execution data against the timeline boundaries.Rule 1 — Dual-Time Presentation: Every active item exposes a runtime-computed Est Start time and a floating Duration Budget ($idealDuration \rightarrow minDuration$).Rule 2 — Systemic Transitions: To mimic human physical constraints, the engine injects a global transitionBufferMinutes (default: 5) between back-to-back tasks.Rule 3 — Micro-Compaction Flow: When a previous task runs late, the delay pushes subsequent item start estimates downstream. When these start estimates collide with an anchor or a soft ceiling, the engine shrinks the remaining flexible items towards their minDuration.Rule 4 — Strategic Priority Shedding: Compaction reduces item time based on priority values. Items with a higher priority number (less important) compress to their absolute floor first before lower-number blocks are altered.Rule 5 — Two-Way Elasticity: The timeline behaves like a rubber band. If a user finishes a compacted task early, skips an entry, or clears space, the engine automatically expands upcoming tasks from their minDuration back up toward their idealDuration.Rule 6 — The Jettison Protocol: If all flexible blocks are compressed to their minDuration and the timeline still breaches a hard anchor wall, the engine drops the least important block (highest priority number) entirely to protect the fixed boundary.Rule 7 — Hard Cutoff Windows: Items can have an optional cutoffTime (e.g., "20:00"). If the engine calculates an Est Start past this time, the task drops instantly, a high-priority system notification fires, and a driftLog event is saved.4.
